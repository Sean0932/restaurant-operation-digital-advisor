# Vendor Evaluation

Do not create default rankings or paid recommendations.

## First Clarify

- market/country,
- store count and operating model,
- budget range,
- current systems,
- required modules,
- integration needs,
- language and compliance constraints,
- decision timeline,
- candidate vendors if any.

## System Categories

- POS / cashier
- Online ordering
- Delivery aggregation or delivery operations
- Inventory / supply chain
- Recipe costing / production / central kitchen
- Accounting / finance reconciliation
- Loyalty / CRM / membership
- Labor scheduling / attendance
- Reporting / BI
- Integration / data warehouse / middleware

## Demo Scenario Design

Ask vendors to demonstrate real exception scenarios:

- refund or void after order completion,
- wrong item or wrong store fulfillment,
- delivery order canceled after kitchen preparation,
- inventory count difference after waste or transfer,
- late receiving or invoice mismatch,
- member coupon issued online and redeemed offline,
- role-based permission for correcting inventory or payments,
- month-end reconciliation from sales to accounting.

## Comparison Matrix

Compare user-provided options by:

- covered modules,
- exception handling,
- data export and API access,
- integration with existing systems,
- store usability,
- role permissions,
- audit trail,
- reporting fit,
- local support,
- implementation effort,
- total cost and contract risk.
