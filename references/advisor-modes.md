# Advisor Modes

Use one mode at a time unless the user asks for a broader review.

## Readiness Check

Use when the user asks for a digital readiness check or asks whether they should buy, replace, or integrate systems.

Output:
- score and stage,
- strongest risks,
- weakest operating-chain dimensions,
- whether to prioritize system, workflow, data handoff, or responsibility,
- next 2-4 actions.

## Vendor & System Selection

Use when the user is looking at POS, inventory, loyalty/CRM, delivery, accounting, labor, reporting, ERP, or integration tools.

Output:
- system category needed,
- must-have scenarios,
- vendor demo questions,
- acceptance checks,
- comparison matrix if the user provides options.

## Operating Workflow Design

Use when the user asks how to organize a restaurant process.

Output:
- current path,
- target path,
- roles,
- required records,
- exception handling,
- checks.

## Issue Diagnosis

Use when the user has a symptom such as inventory mismatch or reconciliation gaps.

Output:
- likely root causes,
- evidence to collect,
- first verification step,
- likely owner,
- next correction action.

## Expansion Readiness

Use when a brand is opening new stores, expanding regions, adding franchisees, or reducing owner dependence.

Output:
- what can already be copied,
- what still depends on people or memory,
- weakest chain before scaling,
- expansion gate checks.

## 30-Day Action Plan

Use after a readiness check or issue diagnosis.

Output weekly actions:
- owner,
- output,
- check method,
- done standard.

### Lightweight Follow-Up Review

Use when the user returns after days or weeks and says they took some actions, want to review progress, or want the next phase.

Do not create a separate mode. Keep the review short:

1. What actions did you take?
   - A. Checked inventory/SKUs
   - B. Organized order, delivery, or online ordering exceptions
   - C. Split reconciliation differences
   - D. Clarified owners, permissions, or review rules
   - E. Adjusted system configuration
   - F. Ran vendor demos or a pilot
   - G. Little progress

2. What improved?
   - A. Inventory gaps reduced
   - B. Reconciliation became faster
   - C. Store backfilling decreased
   - D. Exceptions became easier to explain
   - E. Finance can trace more details
   - F. Stores use the system more consistently
   - G. No obvious improvement yet

3. What is still stuck?
   - A. Store cooperation
   - B. System capability
   - C. Data still does not match
   - D. Finance definitions are not aligned
   - E. Vendors cannot explain exception handling
   - F. Nobody keeps driving the work
   - G. Not sure

Output:
- progress judgment,
- whether the likely root cause changed,
- whether to continue workflow cleanup, start vendor selection, run a pilot, or delay purchase,
- next 2-3 actions.

## Integration & Data Handoff

Use when systems exist but numbers do not match or handoff is unclear.

Output:
- source system,
- downstream system,
- handoff data,
- owner,
- mismatch scenario,
- correction path.
