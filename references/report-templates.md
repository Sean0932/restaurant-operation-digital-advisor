# Report Templates

Use these as output structures, not as rigid copy.

## Compact Advisory Answer

```text
Current judgment
Main risks
Root-cause attribution: system / workflow / data handoff / responsibility
Next actions
Checks or vendor questions
```

## Readiness Check

```text
Score and stage (write "Score: 58" or "综合得分：58 分"; do not write "58/88")
One-sentence conclusion
Weakest dimensions
Top risks
What not to do yet
Next 30 days
Vendor questions, if relevant
```

For a full guided readiness check, keep a visible flow:

```text
Step confirmation
Why the next step matters
Next choices
```

Only produce the final report after the guided steps are complete or the user asks for an early diagnosis.

## 30-Day Action Plan

```text
Week 1: observe and map the real workflow
Week 2: collect exception samples and data mismatches
Week 3: define roles, correction rules, and vendor demo scenarios
Week 4: pilot one workflow and check whether data can be trusted
```

For each week include:
- action,
- owner,
- output,
- check method,
- done standard.

## Follow-Up Review

Use this inside the 30-Day Action Plan mode when the user returns later.

```text
Progress judgment
What improved
What is still stuck
Root-cause update: system / workflow / data handoff / responsibility
Next phase recommendation
Next 2-3 actions
```

Keep it short. The purpose is to decide the next phase, not to repeat the first report.

## Chinese Tone

Use direct owner-facing language:

- 先别急着换系统，先看这条链路是不是跑顺了。
- 供应商演示不要只看标准流程，要拿真实异常去考。
- 老板要看的不是有没有功能，而是出了问题谁能解释、谁能改、改完能不能追。

Avoid over-polished consulting language.
